This page lists file descriptions and non-static function definitions from `runtime/*.c`. It includes every conditional compilation branch, so a listed function may be unavailable on your target. ## g_arena.c

g_arena.c — thread-local region allocator for batch work.

A long-running driver (test runner, LSP) compiles many files in one
process; everything a single compile allocates is dead once its
generated C is handed back. `g_arena_push` switches the checked
allocators over to bump allocation from arena pages; `g_arena_pop`
frees every page at once. Results that must outlive the pop are
deep-copied under a `g_arena_pause` window, which routes allocations
back to the real heap for the duration.

Invariants:
  - Arena pointers exist only while depth > 0; outside a push/pop
    window `g_arena_live` is 0 and ownership checks are a single
    branch on that flag.
  - Every runtime `free` goes through `g_checked_free`, which no-ops
    on arena pointers so they are reclaimed wholesale at pop.

Pages come from `mmap` so a pop returns them to the OS. Handing 1 MiB
pages back to `free` would raise glibc's dynamic mmap threshold above
the page size and force every later page onto the brk heap, pinning
a long-lived driver's resident size at the peak of the largest
compile it ever ran. A bounded free-page pool is kept mapped for
reuse so the common request pays no page-fault overhead.

State is `_Thread_local`; a parallel driver (one compile per thread)
needs no locking.

Disabled under AddressSanitizer: bump allocation hides objects from
ASan's red-zones, which would mask real heap bugs in the compiler's
own data structures. Leak measurement runs on a non-ASan debug build,
so the arena is active there.

### g_arena_alloc

```c
void* g_arena_alloc(size_t n);
```

Bump-allocate `n` bytes from the current arena. Each slot carries a
`GArenaHdr` so `g_arena_owns` recognises it in O(1) and
`g_arena_realloc` can copy its payload. Aborts on OOM.

### g_arena_owns

**Compiled when:** `!defined(__SANITIZE_ADDRESS__)`.

```c
__attribute__((no_sanitize("address"))) int g_arena_owns(void* p);
```

True when `p` was returned by `g_arena_alloc` in the current window.
Confirms containment in a live page before dereferencing the header,
since a non-arena pointer may have unmapped memory immediately
before it (reading there traps).

**Compiled when:** `defined(__SANITIZE_ADDRESS__)`.

```c
int g_arena_owns(void* p);
```

### g_arena_realloc

```c
void* g_arena_realloc(void* p, size_t n);
```

Grow an arena-owned slot to `n` bytes. Returns `p` unchanged if the
old block already fits; otherwise allocates a fresh slot and copies
the old payload over. The old slot is reclaimed at `g_arena_pop`.

### g_arena_push

```c
void g_arena_push(void);
```

Begin a new arena window on this thread. Nestable: only the matching
outermost `g_arena_pop` releases pages.

### g_arena_pop

```c
void g_arena_pop(void);
```

Close one arena window. When the outermost window closes, every page
it mapped is returned to the OS or retained in the free-page pool.

### g_arena_pause

```c
void g_arena_pause(void);
```

Suspend bump allocation without closing the window so a result can be
deep-copied back to libc before the enclosing `g_arena_pop` reclaims
its pages. Nestable.

### g_arena_resume

```c
void g_arena_resume(void);
```

Reverse one `g_arena_pause`. Extra calls are ignored.

### g_arena_ctx_save

```c
void g_arena_ctx_save(GArenaCtx* out);
```

Snapshot the parked fiber's arena state so a context switch can swap
it out (see g_fiber.c). `gen` travels with the context so each
fiber's windows keep their own allocation magic.

### g_arena_ctx_load

```c
void g_arena_ctx_load(const GArenaCtx* in);
```

Install a previously saved context. Marks the sorted index dirty
since the page list has just changed behind its back.

## g_closure.c

g_closure.c — closures (callable function values).

A Gust `Function(P)[R]` value is a `GClosure*`: a function pointer plus
an optional captured environment. Plain function references and
capturing lambdas share this one representation so either can be stored
in a `Function`-typed field, passed as an argument, or called
indirectly. See g_runtime.h for the calling convention.

The captured `env` is an ordinary refcounted heap struct (codegen
synthesizes its type + destructor, which dec_refs any captured heap
values). The closure owns one reference to it and releases it here.

## g_error.c

g_error.c — error handling: the per-thread try stack, the cleanup stack
that releases refcounted locals a `raise` would otherwise strand, and
the two raise entry points (`g_raise` to build error state from a name
and format, `_g_raise_unwind` to longjmp with state already set).

### g_cleanup_push

```c
void g_cleanup_push(void* ptr, GDestructor dtor);
```

Register `{ptr, dtor}` on the cleanup stack, aborting cleanly if the
fixed-size stack would overflow. Generated code calls this immediately
after every refcounted-local declaration inside a try/with body, so an
unwinding longjmp still releases it even though its C variable is out of
scope at the landing site.

### g_cleanup_unwind_to

```c
void g_cleanup_unwind_to(int mark);
```

Exceptional-exit cleanup: invoke the destructor of every entry above
`mark`, innermost first, then truncate back to `mark`. The normal-exit
path writes `g_cleanup_depth = <mark>` inline instead — nothing above
needs its destructor run, since those locals were already released by
the ordinary scope-exit code that ran before this point.

### g_try_push

```c
void g_try_push(void);
```

Push a new try frame, aborting cleanly if the fixed-size stack would
overflow. Generated code calls this immediately before
`setjmp(g_try_stack[g_try_depth - 1])`; centralizing the upper-bound
check here (rather than inlining it in every codegen site) means a
recursive function with a `try` can no longer write a jmp_buf past the
array into adjacent thread-local storage.

### _g_raise_unwind

```c
void _g_raise_unwind(const char* name, const char* message);
```

Unwind to the nearest try frame using the already-set `g_error_class` /
`g_error_data`, or terminate with a message if no try frame exists.

Codegen-only entry point. User-facing C code calls `g_raise` (which builds
state from a name + format and tail-calls here). Called directly by codegen
for a bare re-raise (both args NULL) and for raising a Gust-level error
struct the codegen just populated (`g_error_class`/`g_error_data` pre-set);
`name` and `message` are only read on the uncaught path.

### g_raise

```c
void g_raise(const char* error_name, const char* fmt, ...);
```

Raise `error_name` with a printf-formatted message. The single public
named-raise entry point.

Looks up `error_name` in `_g_error_names[]` to find the id and class
record, allocates a zero-initialized scratch struct sized for any error
type in this binary (`_g_error_max_size`), and sets the first field
(`message`, a GStr* per analyzer requirement) to a GStr of the formatted
text. Other fields read as NULL / zero at the catch site.

Unknown names fall through to the uncaught path with error state cleared,
so a catch arm matches no arm and the uncaught-handler prints cleanly.

## g_fiber.c

g_fiber.c — stackful fibers, per-thread scheduler, epoll netpoller.

Userspace concurrency for scheduler threads. A fiber is a call stack plus
saved callee-saved registers; switching fibers is ~20 instructions of asm,
so "blocking" becomes: park this fiber, run another. `g_sched_enter()`
turns the calling thread into a scheduler thread — its current flow becomes
the main fiber, `g_async_detach` (the `spawn` lowering) creates fibers
instead of pthreads, and the socket layer parks fibers on EAGAIN via
`g_fiber_wait_fd` instead of blocking the thread.

Design invariants:
  - Fibers never migrate between threads, so Gust's non-atomic refcounts
    stay correct: everything a fiber touches lives on its thread.
  - Fiber stacks are fixed virtual reservations (mmap + guard page +
    MAP_NORESERVE): they are never grown or moved, so C-emitted code with
    interior pointers just works and real memory is only the touched pages.
  - Per-fiber runtime state (try stack, error slots, traceback depth,
    arena context) is swapped on every switch; everything else in the
    runtime remains per-thread.
  - One waiter per fd: at most one fiber may be parked on a given fd.

Only compiled on native Linux x86-64/aarch64 (G_HAVE_FIBERS); elsewhere the
entry points are no-op stubs and every existing code path is unchanged.

## g_future.c

g_future.c — pthread-backed futures and detached spawn.

Backs the `def!` / `for!` / `while!` / `spawn` lowerings in codegen. The
single-threaded profiles (emscripten/browser via `GUST_WASM`, bare-metal
via `GUST_FREESTANDING`) share the public API but run everything inline:
the observable result is identical because the runtime always joins before
a dependent use — only the parallelism is dropped.

Spawn `func(args)` on a joinable pthread and return a future that will
carry its result. Aborts the process if the thread cannot be created.

### g_future_get


Return the completed future's result pointer (ownership transfers to the

Join the worker (exactly once) and return the result pointer, which is
now caller-owned. A second call returns the same pointer without

### g_future_free

```c

```

Release the future struct. The result pointer the worker produced is now

Release the future struct. If the worker was never joined (its result

## g_heap.c

g_heap.c — The image's heap, when the image has to bring its own.

An SDK-hosted build gets a heap from the SDK: the Pico SDK and ESP-IDF both
place one and hand malloc the room between the end of .bss and the top of
RAM. A build with no vendor SDK has nobody to do that, so the runtime does
it here — a static array in .bss of exactly GUST_HEAP_BYTES, handed out
through the _sbrk the C library's own malloc grows against.

Bounding it in .bss rather than growing into whatever RAM is left is the
point. The stack descends from the top of RAM and the heap ascends from the
end of .bss, and on a chip with no MMU nothing stands between them: the
failure is a heap allocation quietly writing over a live stack frame, which
presents as a corrupted return address thousands of cycles later. A fixed
array makes the collision a link-time error — the image does not fit — and
makes exhaustion a clean panic at the allocation that asked for too much.

The whole file is conditional: an image whose platform supplies a heap must
not get this _sbrk instead, so a builder that leaves GUST_HEAP_BYTES
undefined compiles an empty translation unit and keeps the platform's own.

C rather than Gust because malloc is what Gust code allocates through: an
allocator written in Gust would call itself on its first line.

### _sbrk

```c
void* _sbrk(ptrdiff_t incr);
```

newlib and picolibc both grow malloc's arena through _sbrk and both read a
-1 return as "no more room", which is what turns exhaustion into a NULL from
malloc and then into the checked allocators' panic. Returning a short block
instead would leave malloc writing past the pool.

### g_heap_supplied_by_platform

```c
int g_heap_supplied_by_platform(void);
```

An image on a platform that places its own heap. Named so the translation
unit is not empty, which is undefined in C.

## g_net.c

g_net.c — shared TCP / socket helpers

Plain POSIX-socket plumbing factored out of the `http` and
`websockets` stdlib packages. These helpers do NOT raise: they return
-1 (and leave `errno` / the supplied stage flag set) so each caller can
raise its own package-specific error message and stay byte-for-byte
identical to its pre-dedup behavior.

### g_tcp_listen_host

```c
int g_tcp_listen_host(const char* host, int port, int* stage, int* gai_rc);
```

getaddrinfo(host, port, AI_PASSIVE) → socket + SO_REUSEADDR + bind + listen
(backlog 128) on the first resolved IPv4 address that works.

`host` NULL or empty binds the wildcard address (0.0.0.0, every interface),
matching the port-only g_tcp_listen; a specific address or name ("127.0.0.1",
"localhost", an interface IP) restricts the socket to it.

Returns the listening fd on success. On failure returns -1 and (when `stage`
is non-NULL) stores which step failed:
  - G_NET_LISTEN_RESOLVE: getaddrinfo failed; its non-zero code is stored in
    `*gai_rc` (when non-NULL) for gai_strerror formatting.
  - G_NET_LISTEN_SOCKET / _BIND / _LISTEN: the syscall that failed, with
    `errno` left as it set it.

### g_tcp_listen

```c
int g_tcp_listen(int port, int* stage);
```

socket + SO_REUSEADDR + bind(INADDR_ANY:port) + listen(backlog 128).

The wildcard-address case of g_tcp_listen_host; see it for the `stage`
contract.

### g_tcp_connect

```c
int g_tcp_connect(const char* host, const char* port, int* gai_rc);
```

getaddrinfo(host, port) → first socket()+connect() that succeeds.

Returns the connected fd on success. On failure returns -1:
  - if getaddrinfo itself failed, stores the non-zero return code in
    `*gai_rc` (when non-NULL) so the caller can format gai_strerror();
  - if every address failed to connect, leaves `*gai_rc == 0`.
`errno` is left as set by the last failing socket()/connect().

### g_send_all

```c
ssize_t g_send_all(int fd, const char* buf, size_t len);
```

MSG_NOSIGNAL keeps a write to a peer that already went away from raising
SIGPIPE, whose default disposition would kill the whole process — one
disconnecting client must not take a server down. Platforms without it fall
back to plain send(); the EPIPE return path is identical either way.

Write all `len` bytes of `buf` to `fd`, looping on short writes.
Returns the number of bytes written (== len) on success, or -1 on a real
error / peer close. A send() interrupted by a signal (EINTR) is retried
rather than reported as failure — important now that g_signal installs
handlers without SA_RESTART, so blocking sends are interruptible.

### g_recv_all

```c
ssize_t g_recv_all(int fd, char* buf, size_t len);
```

Read exactly `len` bytes from `fd` into `buf`, looping on short reads.
Returns `len` on success, or -1 on EOF / real error before `len` bytes.
A recv() interrupted by a signal (EINTR) is retried (see g_send_all).

### g_recv_some

```c
ssize_t g_recv_some(int fd, char* buf, size_t max);
```

Read whatever is available right now, up to `max` bytes, in a single recv().
Unlike g_recv_all this does NOT loop until `max` — it returns as soon as the
first chunk arrives, which is what byte-stream protocol parsers (HTTP, WS)
need when they don't know the length up front.
Returns the byte count (1..max) on success, 0 on a clean peer close (EOF),
or -1 on a real error. A recv() interrupted by a signal (EINTR) is retried
rather than reported as EOF (see g_send_all).

## g_panic.c

g_panic.c — Where a Gust image stops when it cannot go on.

Out of memory, an uncaught raise, a refcount that went negative: each of
these used to print its own message and call exit(1) at the site that found
it. exit() is a hosted notion — it returns to something. A bare-metal image
has nothing to return to, so "stop" has to be spelled out, and how it is
spelled is a property of the image rather than of the fault: a board on a
bench should halt so a debugger can be attached to the wreckage, a deployed
one should reset and come back.

So every fatal path funnels through g_panic() and the strategy is one
compile-time choice:

  GUST_PANIC_EXIT    print, exit(1)          — the hosted default
  GUST_PANIC_ABORT   print, abort()          — leaves a core file
  GUST_PANIC_HALT    print, mask interrupts, spin — the freestanding default
  GUST_PANIC_RESET   print, reset the chip

The message goes out through stdio in every profile: a hosted image has it,
an SDK-hosted one has it retargeted onto USB-CDC or a UART, and the direct
builder retargets it through its own _write. There is no profile where the
runtime has to guess whether it can be heard.

g_stop() is the same ending without a message, for a fault that has already
printed one of its own — an uncaught raise reports the error and its Gust
traceback, and only then asks to be stopped.

This file is C rather than Gust because halting is inline assembly against
the core's interrupt-enable bit and resetting is a store to an architectural
register — neither has a Gust spelling, and the panic path may not allocate,
which is the one thing Gust code cannot promise.

### g_stop

```c
void g_stop(void);
```

End the image without a message, flushing stdio first so anything the fault
already printed makes it out before the chosen strategy takes over.

### g_panic

```c
void g_panic(const char* fmt, ...);
```

Print a formatted fault line to stderr and end the image. The single funnel
every unrecoverable runtime fault (OOM, failed consistency check) goes
through, so the strategy choice is honored once rather than per-caller.

## g_process.c

g_process.c — long-lived child process with live streaming pipes

Backing storage for the stdlib `subprocess` package's `Process` handle.
Unlike g_spawn_capture (which forks, drains to EOF, and returns), a
GProcess keeps the child running and its three stdio pipes open so the
parent can interleave writes to stdin with timed reads of stdout/stderr —
the bidirectional, incremental streaming that a run-to-completion capture
cannot express.

stdout and stderr are kept on separate pipes (capture merges them) so a
newline-delimited protocol on stdout stays clean of diagnostics. All parent
fds are non-blocking; every read is driven by a single poll() with the
caller's timeout, so a read never wedges the whole program.

## g_prof_auto.c

## g_refcount.c

g_refcount.c — reference counting for refcounted heap objects.

Every refcounted struct embeds `GObjectHeader` as its first field.
`g_inc_ref` / `g_dec_ref` cast the object pointer back to
`GObjectHeader*` to read/update the count. When the count hits
zero, the destructor runs to free internal fields, then the outer
struct is `free`d.

Memory ordering follows the standard refcount pattern:
  - inc:  relaxed (the refcount is the only synchronizing data)
  - dec:  acq_rel — the release half publishes any prior writes to
          the destructing thread; the acquire half ensures the
          destructor sees them.

Both are skipped entirely while the program is single-threaded: until
something calls `g_threads_begin` the count is updated with a plain load
and store, since there is no second thread to order against. See
`g_threads_live` in g_runtime.h for why that stays correct once threads
do appear.

Cycles are not yet handled. The `cycle_color` and `flags` fields
in the header are reserved for a future trial-deletion (Bacon-Rajan)
cycle collector.

## g_signal.c

g_signal.c — Unix signal handling.

Two layers:
  1. The OS handler (g_signal_os_handler) runs in async-signal-safe
     context and does the minimum: flip a `volatile sig_atomic_t` trip
     flag. No malloc, no refcount, no printf — none of which are
     async-signal-safe in Gust's runtime.
  2. The registered Gust handler runs *later*, in normal context, when
     the program reaches a `g_signal_poll()` checkpoint — the codegen
     emits one at the top of every loop body. There it may allocate, use
     strings/lists, `raise`, or `exit` freely.

Dispatch is pinned to the thread that installed the handler (the main
thread in practice): the kernel may deliver a signal to any thread, but
only the installing thread runs the Gust handler, so handler code never
races onto a `def!`/`for!` worker. The trip flag is global, so whichever
thread caught the signal, the main thread observes it at its next poll.

### g_signal_install

```c
void g_signal_install(int signum, GClosure* handler);
```

Register a Gust handler for `signum`. A null handler is a no-op (use
g_signal_ignore / g_signal_default to drop a prior handler). Pins
dispatch to the calling thread; callers outside that thread never run
handler code.

### g_signal_dispatch

```c
void g_signal_dispatch(void);
```

Slow path behind the inline poll in g_runtime.h: runs any tripped
handlers in normal context on the installing thread, then clears the
global trip flag. A worker thread that reaches a poll returns without
clearing — the main thread picks the signal up at its next checkpoint.

### g_signal_ignore

```c
void g_signal_ignore(int signum);
```

Drop any registered Gust handler for `signum` and set the kernel
disposition to SIG_IGN — the signal is silently discarded.

### g_signal_default

```c
void g_signal_default(int signum);
```

Drop any registered Gust handler for `signum` and restore the kernel's
default disposition (SIG_DFL — e.g. terminate for SIGINT, dump core for
SIGSEGV).

## g_str.c

g_str.c — refcounted, length-prefixed string objects (GStr)

Background: Gust strings have historically lowered to `char *`
everywhere. That makes ownership invisible to the codegen — the
scope-exit drop pass cannot drop a pointer it cannot tell apart
from a borrow. It also forces every `s.length` access to call
`strlen()`, which is O(N) per call and dominates Lexer hot paths.

GStr fixes both problems:
  - it embeds a refcount header (`G_OBJECT_HEADER`), so the
    ownership tracker can treat it the same as `[]T` / `dict[K,V]`
    / `bytes` — a refcounted heap pointer with `g_inc_ref` /
    `g_dec_ref` semantics.
  - it stores `len` alongside `data`, so `.length` is O(1) and
    downstream operations can use `memcpy`/`memcmp` instead of the
    SSE strlen variants the perf reports keep flagging as a hot
    spot.

Static literals: a sentinel refcount marks a GStr that survives
`g_dec_ref`. Source string literals never reach this file at all —
codegen lowers each one to a statically initialized `static GStr`
through the `G_STR_LIT` macro in g_runtime.h, so a literal costs no
allocation and no first-use check. `g_str_static` builds the same
shape at runtime for strings only the runtime knows.

This file lives next to the existing `g_string.c`. The two are
intentionally separate — `g_string.c` provides the legacy
`char *`-flavored string helpers used by stdlib `.c` glue and
`Buffer`/format internals, and stays around through the Phase A
codegen migration. New runtime entry points should prefer GStr.

What remains here is the GStr object core the Gust-authored module
runtime/g_str.g builds on: constructors and the C-static intern
caches (empty singleton, single-byte table), the
sentinel-refcount paths, the memoized hash, and the variadic
g_str_concat_n / g_str_fmt. The pure string logic (eq/cmp, concat,
split/join, indexing, chr, the FFI takeover bridges) lives in
g_str.g over this exported ABI.

## g_trace.c

g_trace.c — gust-level tracebacks for fatal signals.

Pure refcounting + checked operations catch most bad accesses and raise a
normal Gust error, but a few faults (null/OOB deref a check missed, stack
overflow from runaway recursion, a compiler/FFI bug) reach the hardware as
SIGSEGV/SIGBUS/SIGFPE/SIGILL. By default those produce a bare "exit 139"
with no context. This module turns them into a labelled diagnostic plus a
traceback.

Two layers:
  1. A thread-local SHADOW CALL STACK. Codegen emits `g_frame_push(func,
     file, line)` at each function entry and arranges a matching pop on
     exit (via __attribute__((cleanup)) so every return path pops). The
     fatal-signal handler walks it to print real `.g` frames. This is
     opt-in at codegen time; with no frames emitted the stack is simply
     empty and only layer (2) runs.
  2. A fatal-signal handler that prints the signal name, the shadow-stack
     traceback, and a best-effort C backtrace, then re-raises with the
     default disposition so the real exit status / core dump still happen.

The handler runs on an ALTERNATE STACK (sigaltstack) so a stack-overflow
SIGSEGV — where the normal stack is exhausted — can still be reported. It
uses only async-signal-safe primitives (write(2), no malloc/printf).

signal.h is included here, never in g_runtime.h: the umbrella header is
included by generated code, where the SIGxxx macros would rewrite any
Gust local, field or member spelled `SIGINT`.

### g_frame_push

```c
void g_frame_push(const char* func, const char* file, int64_t line);
```

Record a function entry on the thread's shadow call stack. Codegen emits
one call per function via the G_FRAME macro. `func` and `file` are string
literals owned by the TU — the stack stores pointers, not copies. The depth
counter advances even when a slot would fall past G_FRAME_STACK_MAX so
push/pop stay balanced; over-cap frames are counted but not stored.

### g_frame_top

```c
int g_frame_top(const char** func, const char** package, int64_t* line);
```

Identity of the innermost recorded frame, for the `--trace` exception event.
Returns 0 when the shadow stack is empty or its top frame fell past the cap
(over-cap frames are counted but not stored, so they have nothing to report).
`func` and `package` are the literals codegen passed to G_FRAME.

### g_frame_cleanup

```c
void g_frame_cleanup(int* unused);
```

Pop one frame on any normal scope exit. Reached only through the
`__attribute__((cleanup(g_frame_cleanup)))` the G_FRAME macro installs on
a dummy local. longjmp does NOT run cleanups, so the try machinery restores
g_frame_depth separately.

### g_print_raise_traceback

```c

```

Traceback for an uncaught raise, called from generated code at the top-level
catch. g_frame_depth has already unwound to the handler, so this walks to

## g_trace_hook.c

g_trace_hook.c — the `--trace` execution hook.

`gust build --trace` makes codegen emit `g_trace_call(...)` at the entry of
every generated function body and `g_trace_return(...)` immediately before
each of its returns; `g_raise` reports `g_trace_exception(...)`. Only
`.g`-derived bodies pass through codegen, so hand-written runtime and
package C is never instrumented and the events carry clean Gust names.

A traced program observes nothing until it calls `trace.set_hook`, which
installs two things here: the Gust callback (a GClosure) and the address of
the trace package's dispatcher — the Gust function that knows how to build a
`TraceInfo` and call that callback. Keeping the dispatcher behind a function
pointer is what lets this module stay ignorant of every Gust struct layout,
and what lets a program that never imports `trace` link without it: the
pointer stays NULL and each event returns immediately.

The event being reported lives in a thread-local slot the dispatcher reads
back through the `g_trace_frame_*` accessors, rather than being passed as
arguments. That keeps the C ABI codegen emits narrow and fixed, and lets the
Gust side pull only the fields its hook actually looks at.

Re-entrancy: the hook is itself a Gust function, so it is instrumented like
any other and would recurse forever. `busy` suppresses every event raised
while a dispatch is in flight — the hook's own body, and anything it calls,
report nothing.
