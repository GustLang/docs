```gust
use http.server
```

The `Server` object: construction (`serve`/`Server(port:)`), route
registration (`get`/`post`/...), before/after middleware, static-file
mounts, route groups, and the accept loop. The route table, middleware,
and mounts live here as plain Gust data — registering a route is a list
append, with no socket involved. The socket is bound lazily, only when
`run`/`next` actually needs it. Dispatch logic lives in `dispatch.g`.
Part of the `http.server` package.

<Note>
Only available where `target == "native" or has("sockets")`.
</Note>

## `Next`

<a id="Next" />
One link in the middleware chain. Holds the server (whose middleware
list and routes drive dispatch) and the index of the next middleware to
run. A middleware calls `next.call(req)` to advance to the following
layer — or, once the middleware is exhausted, to routing. Reifying the
"next handler" as data is how the onion model is expressed without
closures: each `call` builds a fresh `Next` advanced by one.

```gust
def Next

    server: Server
    index: integer

end
```

**Fields**

- `server: Server` — The server whose middleware list and routes back this chain.
- `index: integer` — Index into `server.middlewares` of the next layer to run.

**Methods**

<a id="Next.call" />
```gust
def Next.call(req: Request) -> Response
```

Invoke the next middleware layer with a `Next` advanced past it, or —
when every middleware has run — hand off to `server._route` for path
matching, static files, and 404/405.

**Parameters**

- `req` — The request flowing down the chain.

## `Middleware`

<a id="Middleware" />
Base class for class-based middleware. Extend it and override `handle`
to wrap every request: read or rewrite the Request on the way in, call
`next.call(request)` to invoke the rest of the chain, then read or rewrite
the Response on the way out — or return a Response without calling `next`
to short-circuit (e.g. an early `unauthorized()`). Whatever state the
middleware needs — configuration, dependencies — lives in its own fields.

Register an instance with `server.use(MyMiddleware(...))`. Middleware run
outermost-first in registration order: the first registered wraps every
one registered after it, and routing sits at the core.

**Methods**

<a id="Middleware.handle" />
```gust
def Middleware.handle(request: Request, next: Next) -> Response
```

Process one request and return the Response to send. The default passes
the request straight through to the rest of the chain unchanged; override
it to do work before and/or after the downstream handler.

**Parameters**

- `request` — The request flowing down the chain.
- `next` — The next link in the chain; call `next.call(request)` to invoke the remaining middleware and then routing.

**Examples**

```gust
def AuthMiddleware extends http.Middleware
    header: string
end

def AuthMiddleware.handle(request: http.Request, next: http.Next) -> http.Response
    if request.headers.get(header) == ""
        return http.unauthorized("missing token")
    end
    return next.call(request)
end

app.use(AuthMiddleware(header: "Authorization"))
```

## `Request`

<a id="Request" />
An incoming HTTP request, passed to every route handler. Read its
method, path, headers, captured path params, query params, and body;
parse a JSON body with `json`.

```gust
def Request

    method: string
    path: string
    headers: http.Headers
    body: string
    remote_ip: string
    version: string
    query_params: dict[string, string]
    path_params: dict[string, string]

end
```

**Fields**

- `method: string` — HTTP method (e.g. "GET", "POST"), uppercased.
- `path: string` — Request path with the query string stripped, e.g. "/users".
- `headers: http.Headers` — Request headers as a `Headers` view. Use `headers.get(name)` or `headers[name]` (case-insensitive, "" if absent).
- `body: string` — Raw request body.
- `remote_ip: string` — Client IP address as text (empty if unavailable).
- `version: string` — HTTP version token, e.g. "HTTP/1.1".
- `query_params: dict[string, string]` — Parsed query-string parameters. Use `query_param(name)`.
- `path_params: dict[string, string]` — Captured `{name}` route segments. Use `path_param(name)`.

**Methods**

<a id="Request.path_param" />
```gust
def Request.path_param(name: string) -> string
```

Look up a captured `{name}` route segment, or "" if absent.

**Parameters**

- `name` — Path-parameter name (the `{name}` in the route pattern).

---

<a id="Request.query_param" />
```gust
def Request.query_param(name: string) -> string
```

Look up a query-string parameter, or "" if absent.

**Parameters**

- `name` — Query-parameter name.

---

<a id="Request.cookie" />
```gust
def Request.cookie(name: string) -> string
```

Look up a cookie value from the `Cookie` header, or "" if absent.

**Parameters**

- `name` — Cookie name.

---

<a id="Request.is_json" />
```gust
def Request.is_json() -> bool
```

True when the request's Content-Type announces JSON.

---

<a id="Request.json" />
```gust
def Request.json() -> Any
```

Parse the request body as JSON into native Gust values: an object
becomes a `dict[string, Any]`, an array a `list[Any]`, and scalars their
matching primitive.

**Raises**

- `ValueError` — the request body is not valid JSON.

**Examples**

```gust
def show_user(req: http.Request) -> http.Response
    id := req.path_param("id")
    page := req.query_param("page")
    return http.ok(f"user {id}, page {page}")
end
```

## `Response`

<a id="Response" />
An HTTP response. Returned from a handler. Prefer the constructors
(`ok`, `text`, `html`, `json_response`, `redirect`, `not_found`, ...)
over building one by hand. Chain `with_header`/`with_cookie` to add
response headers.

```gust
def Response

    status: integer
    body: string
    content_type: string
    headers: dict[string, list[string]]
    _file: string

end
```

**Fields**

- `status: integer` — HTTP status code (e.g. 200, 404). A status of 0 is the internal "no match" signal from static-file resolution.
- `body: string` — Response body.
- `content_type: string` — The value for the Content-Type header.
- `headers: dict[string, list[string]]` — Extra response headers as a field set — lowercased name to that header's lines. Build it with `with_header`/`with_cookie`. Reserved headers (Content-Type/Length, Connection) are ignored here.
- `_file: string` — Internal — when non-empty, the framework streams this file's raw bytes as the body (binary-safe), ignoring `body`. Set via `with_file`; used by static-file serving.

**Methods**

<a id="Response.with_header" />
```gust
def Response.with_header(name: string, value: string) -> Response
```

Set a response header, replacing any value already set under that name
(matched case-insensitively), and return this same Response so calls chain.
Reserved headers (Content-Type/Content-Length/Connection) are managed
by the framework and any set here are ignored when the response is sent.

A header whose value is defined as a comma-separated list takes that list
as one value, e.g. `with_header("Vary", "Accept, Accept-Encoding")`: the
only header a response may repeat is `Set-Cookie`, which `with_cookie`
writes.

**Parameters**

- `name` — Header name.
- `value` — Header value.

---

<a id="Response.with_cookie" />
```gust
def Response.with_cookie(name: string, value: string) -> Response
```

Add a `Set-Cookie: name=value; Path=/` header and return this
Response so calls chain. Each call adds a cookie of its own: `Set-Cookie`
is sent as one line per cookie, never comma-joined, since a cookie's
`Expires` date contains a comma.

**Parameters**

- `name` — Cookie name.
- `value` — Cookie value (not percent-encoded — keep it token-safe).

---

<a id="Response.with_file" />
```gust
def Response.with_file(path: string) -> Response
```

Stream the raw bytes of the file at `path` as the body (binary-safe),
ignoring the `body` field. Returns this same Response so calls chain.
Used by static-file serving; the Content-Length is computed by the
framework when the response is sent.

**Parameters**

- `path` — Filesystem path of the file to stream.

**Examples**

```gust
def create(req: http.Request) -> http.Response
    return http.json_response({"id": 1}, 201).with_header("X-Api", "v1")
end
```

## `Route`

<a id="Route" />
One registered route: an HTTP method, a path pattern (which may
contain `{name}` capture segments), and the handler to invoke.

```gust
def Route

    method: string
    pattern: string
    segments: list[string]
    handler: Function(Request)[Response]

end
```

**Fields**

- `method: string` — HTTP method to match (e.g. "GET").
- `pattern: string` — Path pattern, e.g. "/users/&#123;id&#125;".
- `segments: list[string]` — `pattern` pre-split into non-empty path segments, computed once at registration so matching a request needs no re-split.
- `handler: Function(Request)[Response]` — Function invoked with the Request, returning a Response.

## `Server`

<a id="Server" />
A routed HTTP/1.1 server built on the `socket` package — the whole
request lifecycle is pure Gust (parse, match, middleware, respond); only
the accept loop touches C. Registration is just data: `get`/`post`/...,
`middleware`, and `static` append to in-memory lists, so the socket stays
unbound until the first `run`/`next` lazily binds it (a bind failure
surfaces there as an `IOError` — or eagerly, if you built it with
`serve(port)`).

Wire handlers up imperatively or with a registration decorator — both
register the same route.
On each request the server runs before-middleware outermost-first, matches
the first route whose method and `{name}`-pattern fit (else a static mount,
else `404`; a path match with the wrong method is `405`), runs
after-middleware, and sends the `Response`. A handler that raises becomes
`500`. `run` returns once another thread calls `close`.

```gust
def Server

    port: integer
    routes: list[Route]
    middlewares: list[Middleware]
    statics: list[StaticMount]
    websocket_routes: list[WsRoute]
    _handle: integer
    _worker_handles: list[integer]
    _closed: ref[bool]

end
```

**Fields**

- `port: integer` — TCP port to listen on.
- `routes: list[Route]` — Registered routes, matched in order.
- `middlewares: list[Middleware]` — Middleware layers, applied outermost-first around routing; each `handle`s the Request with a `Next` chain link. Class-based middleware register via `use`, functions via `middleware`.
- `statics: list[StaticMount]` — Static-file mounts, checked after dynamic routes miss.
- `websocket_routes: list[WsRoute]` — WebSocket routes, matched on a request that carries a WebSocket `Upgrade` header before normal HTTP dispatch.
- `_handle: integer`
- `_worker_handles: list[integer]`
- `_closed: ref[bool]`

**Methods**

```gust
def Server.route(
    method: string,

```

Register a handler for an HTTP method + path pattern. Patterns may
contain `{name}` segments that match one path segment and are exposed
via `req.path_param(name)`. Routes are matched in registration order.

**Parameters**

- `method` — HTTP method to match (e.g. "GET").
- `path` — Path pattern, e.g. "/users/&#123;id&#125;".
- `handler` — Function invoked with the Request, returning a Response.

<a id="Server.websocket" />
```gust
def Server.websocket(
    handler: Function(Request, websockets.Connection)[none],
    path: string,
) -> Function(Request, websockets.Connection)[none]
```

Register a WebSocket handler served on the same port as the HTTP routes.
When a request arrives carrying a WebSocket `Upgrade` header and a path
matching `path`, the server completes the opening handshake and invokes
`handler` with the Request (carrying any captured `{name}` path params) and
the open `websockets.Connection`; the connection is closed once the handler
returns. Patterns may contain `{name}` capture segments, matched exactly as
HTTP routes are. WebSocket routes are checked before HTTP dispatch, so a
non-upgrade request to the same path still flows to the HTTP routes.

Register imperatively or with a decorator — both register the same route.

**Parameters**

- `handler` — Function invoked with the Request and the upgraded Connection.
- `path` — Path pattern to match, e.g. "/ws" or "/ws/&#123;room&#125;".

**Returns** `Function(Request, websockets.Connection)[none]`

`handler` unchanged, so the method also serves as an
`@app.websocket(path)` decorator.

**Examples**

```gust
app.websocket(chat, "/ws/{room}")   # or register by hand

@app.websocket("/ws/{room}")
def chat(req: http.Request, conn: websockets.Connection) -> none
    conn.send(f"joined {req.path_param("room")}")
end
```

<a id="Server.use" />
```gust
def Server.use(mw: Middleware) -> none
```

Register a class-based middleware wrapping every request. Extend the
`Middleware` base class and override `handle`; then register an instance
here. Its `handle` does work, then either calls `next.call(req)` to invoke
the rest of the chain (the remaining middleware, then routing) or returns a
Response directly to short-circuit. Wrap `next.call(req)` to read/rewrite
the response (add headers, log); skip it to bail out early (e.g.
`unauthorized()`). Middleware run outermost-first in registration order:
the first registered is the outermost layer, wrapping all those registered
after — `use` and `middleware` share one chain in a single order.

**Parameters**

- `mw` — The middleware instance whose `handle` runs on every request.

---

<a id="Server.middleware" />
```gust
def Server.middleware(handler: Function(Request, Next)[Response]) -> Function(Request, Next)[Response]
```

Register a function as middleware wrapping every request. A middleware
receives the Request and a `Next` chain link; it does work, then either
calls `next.call(req)` to invoke the rest of the chain (the remaining
middleware, then routing) or returns a Response directly to short-circuit.
Wrap the `next.call(req)` to read/rewrite the response (add headers, log);
skip it to bail out early (e.g. `unauthorized()`). Middleware run
outermost-first in registration order: the first registered is the
outermost layer, wrapping all those registered after. For middleware that
carries state, extend the `Middleware` base class and register with `use`.

**Parameters**

- `handler` — Function invoked with the Request and the Next chain link, returning the Response to send.

**Returns** `Function(Request, Next)[Response]`

`handler` unchanged, so the method also serves as an `@app.middleware`
decorator.

---

<a id="Server.run" />
```gust
def Server.run() -> none
```

Block forever, serving every accepted connection as a lightweight
fiber. One scheduler thread runs per CPU, all accepting from the shared
listening socket; a connection is served on the thread that accepted it,
and thousands of idle connections cost pages of memory rather than
threads. Each request is parsed and handed to the Gust dispatcher, which
runs before-middleware, matches a route (or a static mount), runs
after-middleware, and returns the Response the fiber then sends.
Unmatched paths get `404 Not Found`; a path that matches but not its
method gets `405 Method Not Allowed`. A handler that raises becomes
`500 Internal Server Error`. Returns when the listening socket is closed
(e.g. another thread calls `server.close()`).

Connections are persistent: a fiber keeps serving requests off its
connection until the client asks to close it (`Connection: close`, or an
HTTP/1.0 request that does not ask to keep it open) or goes away. A client
issuing many requests therefore pays for one connection and one fiber
rather than one of each per request.

**Raises**

- `IOError` — the listening socket cannot be bound on first use (for example, the port is already in use).

---

<a id="Server.close" />
```gust
def Server.close() -> none
```

Stop accepting new connections. Causes a concurrent `run()`
call to return. A no-op on a server that never bound.

**Examples**

```gust
use http.server
app: constant[server.Server] = server.Server(port: 8080)

@app.get("/users/{id}")
def show_user(req: http.Request) -> http.Response
    return http.ok(f"user {req.path_param("id")}")
end

app.get(home, "/")          # or register by hand
app.run()                   # blocks; a thread per connection
```

<a id="http.server.json_response" />


An `application/json` body, `200 OK` by default, serializing `body` to
compact JSON. `body` may be any value — a primitive, list, dict, or struct (a
struct serializes through its `__dict` conversion).

**Parameters**

- `body: Any` — The response object to serialize and send.
- `status_code: integer` — HTTP status code to send.
