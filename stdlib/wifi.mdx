```gust
use wifi
```

The on-board radio: power, station and access-point modes, connect (blocking /
async / explicit auth), link status, scanning, signal / MAC, and power-save.
One neutral API over a backend per platform:

- Raspberry Pi Pico W / 2 W: the CYW43 chip through the Pico SDK
  (pico_cyw43_arch + cyw43_ctrl).
- ESP32 (ESP-IDF): the chip's own radio through esp_wifi + esp_netif.

Targets with no radio this package drives have no `wifi` package: an import
there resolves to nothing and every reference is a compile error, rather than a
misleading no-op. On the Pico that means the wireless boards only — the plain
`pico` and `pico2` have no CYW43.

`connect`/`scan`/etc. lazily power the radio up, so the common path is just
`wifi.connect(...)`; the lifecycle calls below are for finer control (AP mode,
power management, turning the radio off).

A radio that can also receive frames not addressed to it — the ESP32 family —
carries a third mode alongside these, entered with `enable_monitor` and read
with `capture`.

**Examples**

```gust
use wifi

def main() -> none
    if wifi.connect("my-ssid", "my-passphrase", 30000)
        print(wifi.ip())    # e.g. 192.168.1.42
    end
end
```

## `FrameKind`

<a id="FrameKind" />
```gust
enum FrameKind: integer
```

<Note>
Only available where `has("wifi-monitor")`.
</Note>

The class of a captured frame, as the receiver classified it.

**Variants**

- `management = 0` — Beacons, probes, authentication, association — the frames that run the network rather than carry traffic.
- `control = 1` — Medium-access frames: RTS/CTS, acknowledgements, block-ack, PS-Poll.
- `data = 2` — Frames carrying a payload, encrypted or not.
- `misc = 3` — Anything the receiver decoded but does not classify. The frame body is empty, and only the radio metadata is meaningful.

## `SecondaryChannel`

<a id="SecondaryChannel" />
```gust
enum SecondaryChannel: integer
```

<Note>
Only available where `has("wifi-monitor")`.
</Note>

Where the second 20 MHz channel of a 40 MHz-wide channel sits relative
to the primary one, passed to `set_channel`.

**Variants**

- `off = 0` — A single 20 MHz channel. The usual choice, and the one that sees every frame sent to a 20 MHz station.
- `above = 1` — The secondary channel is the one above the primary.
- `below = 2` — The secondary channel is the one below the primary.

## `FrameFilter`

<a id="FrameFilter" />
```gust
enum FrameFilter: integer
```

<Note>
Only available where `has("wifi-monitor")`.
</Note>

Which classes of frame reach the capture queue, passed to
`capture_filter`. Combine classes with `|`, e.g.
`FrameFilter.management | FrameFilter.data`.

The receiver applies this before a frame reaches the queue, so filtering
narrowly is what keeps a busy channel from overrunning it.

**Variants**

- `management = 1` — Beacons, probes, authentication, association.
- `control = 2` — RTS/CTS, acknowledgements, block-ack, PS-Poll. Narrow these further with `control_filter`.
- `data = 4` — Frames carrying a payload.
- `misc = 8` — Frames the receiver decoded but does not classify.
- `data_mpdu = 16` — Data frames sent on their own.
- `data_ampdu = 32` — Data frames sent aggregated with others.
- `fcs_fail = 64` — Frames whose checksum did not verify. Left out of `all` because a failed check means the bytes are wrong somewhere and nothing says where.
- `all = 63` — Every class whose contents can be trusted — everything but `fcs_fail`. What a fresh `enable_monitor` installs.

## `ControlFilter`

<a id="ControlFilter" />
```gust
enum ControlFilter: integer
```

<Note>
Only available where `has("wifi-monitor")`.
</Note>

Which control subtypes reach the queue once `FrameFilter.control` has
admitted the class at all, passed to `control_filter`. Combine subtypes
with `|`, e.g. `ControlFilter.rts | ControlFilter.cts`.

Acknowledgements alone can outnumber every other frame on a busy channel,
which is the usual reason to narrow this.

**Variants**

- `wrapper = 8388608` — Control Wrapper, which carries another control frame.
- `block_ack_request = 16777216` — A request to acknowledge a block of frames.
- `block_ack = 33554432` — The acknowledgement of such a block.
- `ps_poll = 67108864` — A sleeping station asking its access point for buffered traffic.
- `rts = 134217728` — Request To Send, which reserves the medium.
- `cts = 268435456` — Clear To Send, the reply that grants it.
- `ack = 536870912` — The acknowledgement of a single frame.
- `cf_end = 1073741824` — The end of a contention-free period.
- `cf_end_ack = 2147483648` — The end of a contention-free period, acknowledging with it.
- `all = 4286578688` — Every control subtype. What a fresh `enable_monitor` installs.

**Variants**

## `CsiReading`

<a id="CsiReading" />
<Note>
Only available where `has("wifi-csi")`.
</Note>

One CSI report: the raw channel measurement for a received frame, and
what the radio measured while receiving it.

```gust
def CsiReading

    data: bytes
    source: string
    rssi: integer
    channel: integer
    rate: integer
    noise_floor: integer
    timestamp_us: integer

end
```

**Fields**

- `data: bytes` — The CSI itself — signed 8-bit (imaginary, real) pairs, one pair per subcarrier. The length varies with the frame's bandwidth.
- `source: string` — The address the measured frame was sent from, as `"aa:bb:cc:dd:ee:ff"`.
- `rssi: integer` — Received signal strength in dBm; negative, closer to zero for a stronger signal.
- `channel: integer` — The primary channel the frame arrived on.
- `rate: integer` — The PHY rate the frame was sent at, in the radio's own encoding.
- `noise_floor: integer` — The measured noise floor in dBm. `rssi` minus this is the signal-to-noise ratio.
- `timestamp_us: integer` — The receiver's local clock in microseconds when the frame arrived.

## `Frame`

<a id="Frame" />
<Note>
Only available where `has("wifi-monitor")`.
</Note>

One frame received in monitor mode, with what the radio measured while
receiving it.

```gust
def Frame

    data: bytes
    kind: FrameKind
    rssi: integer
    channel: integer
    rate: integer
    noise_floor: integer
    timestamp_us: integer

end
```

**Fields**

- `data: bytes` — The frame as it was transmitted, from the frame-control field onward, with the trailing checksum removed. Truncated to the per-frame limit given to `enable_monitor`, so a long frame is reported short rather than dropped — compare `data.length` against that limit to tell whether a body was cut off.
- `kind: FrameKind` — Which class of frame this is.
- `rssi: integer` — Received signal strength in dBm; negative, and closer to zero for a stronger signal.
- `channel: integer` — The primary channel the frame arrived on.
- `rate: integer` — The PHY rate the frame was sent at, in the radio's own encoding. Meaningful only for legacy (802.11b/g) frames.
- `noise_floor: integer` — The measured noise floor in dBm. `rssi` minus this is the signal-to-noise ratio.
- `timestamp_us: integer` — The receiver's local clock in microseconds when the frame arrived. Precise only while neither modem sleep nor light sleep is enabled.

**Methods**

<a id="Frame.subtype" />
```gust
def Frame.subtype() -> integer
```

The four-bit subtype from the frame-control field, which says what the
frame is within its class — for management frames 8 is a beacon, 4 a probe
request, 5 a probe response; for control frames 11 is RTS and 13 an
acknowledgement. Zero when the frame is too short to carry one.

---

<a id="Frame.destination" />
```gust

```

The address the frame is addressed to, as `"aa:bb:cc:dd:ee:ff"`, or ""
when the frame does not carry one. `"ff:ff:ff:ff:ff:ff"` is the broadcast
address.

---

<a id="Frame.source" />
```gust
def Frame.source() -> string
```

The address the frame was sent from, as `"aa:bb:cc:dd:ee:ff"`, or ""
when the frame does not carry one — a bare acknowledgement names only its
receiver, for instance.

---

<a id="Frame.bssid" />
```gust
def Frame.bssid() -> string
```

The address of the network the frame belongs to, as
`"aa:bb:cc:dd:ee:ff"` — the access point's own address on an infrastructure
network. "" when the frame names no network, which is the case for a frame
bridged between two access points and for most control frames.

<a id="wifi.enable_ap_dhcp" />
```gust
def foreign enable_ap_dhcp() -> bool
```

Start handing out addresses on the access point, and report whether the
server is now running. Idempotent.

A station that associates has no address of its own and no way to reach the
board until it is given one, so an access point serving anything needs this
as well as `enable_ap`. Addresses come from the access-point interface's own
subnet — 192.168.4.0/24, the board itself being 192.168.4.1 — and are handed
out with the board as both the route off the network and the name server on
it, which is what points a station at the board for everything.

A station keeps the address it was given across a reconnect, and a board
serving more stations than it has room for gives the longest-idle address
away rather than refusing the newest station.

On the ESP32 the chip's own network layer already runs this server and
`enable_ap` starts it, so there this call does nothing and answers true.

**Returns** `bool`

Whether addresses are now being served. False when the access point is
not up, or the address server could not take its port.

<a id="wifi.inject" />
```gust
def inject(frame: bytes, system_seq: bool) -> bool
```

<Note>
Only available where `has("wifi-monitor")`.
</Note>

Transmit `frame` on the radio's current channel, returning true if the
hardware accepted it for transmission. False if the frame is shorter than a
frame-control-plus-address header or longer than the transmit path takes, or
if the radio is not running.

The frame is sent as written, without the trailing checksum — the hardware
adds that. Success means the radio queued the frame, not that anything
received it.

**Parameters**

- `frame: bytes` — The 802.11 frame from the frame-control field onward, without a checksum.
- `system_seq: bool` — Whether the hardware fills in the sequence-control field. Leave true to have the system own sequence numbers; false to send the field exactly as `frame` carries it.

<a id="wifi.enable_monitor" />
```gust
def enable_monitor(channel: integer, queue: integer, max_frame: integer) -> bool
```

<Note>
Only available where `has("wifi-monitor")`.
</Note>

Put the radio in monitor mode on `channel` and start capturing. Returns
true once the receiver is running; false if the radio could not be started
or the queue could not be allocated.

Powers the radio up if it is not up already, and turns power saving off so
the receiver stays awake between frames.

**Parameters**

- `channel: integer` — The channel to park on, 1 to 14. Values outside that range leave the radio on the channel it is already using.
- `queue: integer` — How many frames may wait to be read. A frame arriving with the queue full is dropped, so a queue has to cover the longest gap between `capture` calls.
- `max_frame: integer` — How many bytes to keep from each frame. Frames longer than this are truncated; 256 keeps every header and the start of the body, and the full 2346 keeps whatever arrives.

```gust
def capture(timeout_ms: integer) -> Frame | none
```

<a id="wifi.scan" />
```gust
def scan() -> list[Network]
```

Perform a blocking scan and return every nearby network found, in the
