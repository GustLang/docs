```gust
use os
```

System-level utilities: the operating-system and hardware identity (platform,
OS version, architecture, hostname, byte order), process identity through
`process()` (pid, ppid, uid, username, executable path, command-line
arguments), standard-stream I/O,
executable lookup on `$PATH`, and a per-compile arena allocator for batch
drivers.

**Examples**

```gust
use os

def main() -> none
    print(os.hostname())
    print(os.process().pid)
end
```

A bare-metal target has no host identity and no process table, so the
declarations naming one do not exist there. The TI calculators drop more: their
C library has no environment and no file descriptors, so `env`, `set_env`, the
`open_fd`/`read_fd`/`write_fd` layer with the `o_*` flags and `*_fileno`
descriptors it takes, the stdin readers built on it, and `which` are absent on
that family. What every target
keeps is `platform`, `args`, `executable`, `stdout_write`, the TTY probes,
`exit_process`, `errno`/`strerror` and the arena.

**Fields**

- `pid: integer` — Process id.
- `name: string` — The filename of the executable, without its enclosing parens.
- `state: string` — Process state code, e.g. "R" (running), "S" (sleeping), "D" (uninterruptible sleep), "Z" (zombie), "T" (stopped).
- `ppid: integer` — Parent process id.
- `pgrp: integer` — Process group id.
- `session: integer` — Session id.
- `tty_nr: integer` — Controlling terminal of the process.
- `tpgid: integer` — Id of the foreground process group of the controlling terminal.
- `flags: integer` — Kernel flags word of the process (`PF_*` constants).
- `minflt: integer` — Number of minor faults the process has made that did not require loading a memory page from disk.
- `cminflt: integer` — Number of minor faults made by the process's waited-for children.
- `majflt: integer` — Number of major faults the process has made that required loading a memory page from disk.
- `cmajflt: integer` — Number of major faults made by the process's waited-for children.
- `utime: integer` — Time the process has spent in user mode, in clock ticks.
- `stime: integer` — Time the process has spent in kernel mode, in clock ticks.
- `cutime: integer` — Time the process's waited-for children have spent in user mode, in clock ticks.
- `cstime: integer` — Time the process's waited-for children have spent in kernel mode, in clock ticks.
- `priority: integer` — Scheduling priority.
- `nice: integer` — Nice value, in the range 19 (low priority) to -20 (high priority).
- `num_threads: integer` — Number of threads in the process.
- `itrealvalue: integer` — Time in jiffies before the next SIGALRM is sent, always 0.
- `starttime: integer` — Time the process started after system boot, in clock ticks.
- `vsize: integer` — Virtual memory size in bytes.
- `rss: integer` — Resident set size, in pages.
- `rsslim: integer` — Current soft limit in bytes on the rss of the process.
- `startcode: integer` — Address above which program text can run.
- `endcode: integer` — Address below which program text can run.
- `startstack: integer` — Address of the start (bottom) of the stack.
- `kstkesp: integer` — Current value of the stack pointer (ESP), as found in the kernel stack page for the process.
- `kstkeip: integer` — Current value of the instruction pointer (EIP).
- `signal: integer` — Bitmap of pending signals, displayed as a decimal number.
- `blocked: integer` — Bitmap of blocked signals.
- `sigignore: integer` — Bitmap of ignored signals.
- `sigcatch: integer` — Bitmap of caught signals.
- `wchan: integer` — Address of the kernel function where the process is sleeping.
- `nswap: integer` — Number of pages swapped, always 0 on modern kernels.
- `cnswap: integer` — Cumulative nswap for waited-for children, always 0.
- `exit_signal: integer` — Signal sent to the parent when the process dies.
- `processor: integer` — CPU number the process was last executed on.
- `rt_priority: integer` — Real-time scheduling priority.
- `policy: integer` — Scheduling policy.
- `delayacct_blkio_ticks: integer` — Aggregated block I/O delays, in clock ticks.
- `guest_time: integer` — Time spent running a virtual CPU for a guest OS, in clock ticks.
- `cguest_time: integer` — Guest time of the process's children, in clock ticks.
- `start_data: integer` — Address above which program initialized and uninitialized (BSS) data are placed.
- `end_data: integer` — Address below which program initialized and uninitialized (BSS) data are placed.
- `start_brk: integer` — Address above which the program heap can be expanded with brk.
- `arg_start: integer` — Address above which command-line arguments are placed.
- `arg_end: integer` — Address below which command-line arguments are placed.
- `env_start: integer` — Address above which environment variables are placed.
- `env_end: integer` — Address below which environment variables are placed.
- `exit_code: integer` — The thread's exit status.

<a id="Process.set_name" />
```gust
def Process.set_name(new_name: string) -> none
```

Set the calling thread's name, as reported by `/proc/self/comm`.

The command line is untouched: `args()` and the full command shown by a
process listing are unaffected. Called from a thread other than the main
one, only that thread is renamed.

**Parameters**

- `new_name` — Replacement name, 1-15 bytes. The kernel reserves the sixteenth byte for the terminator.

**Raises**

- `ValueError` — `new_name` is empty or longer than 15 bytes.

<a id="os.setvbuf" />
```gust
def foreign setvbuf(fd: integer, mode: BufferMode, size: integer) -> integer
```

<Note>
Not available on freestanding builds.
</Note>

Choose how C buffers one of the standard streams, naming it by descriptor
(0=stdin, 1=stdout, 2=stderr). Returns 0, or -1 with `errno` set.

`iofbf` fills a buffer of `size` bytes before writing, `iolbf` writes a line
at a time, and `ionbf` writes straight through. A `size` of 0 or less takes
the C library's default; `ionbf` ignores it. The C library owns the buffer —
there is no way to supply one, because stdio writes into it for the life of
the stream, which no Gust value outlives.

Call this before the stream carries any traffic. Changing the buffering of a
stream already in use is undefined in C, and the process writes its banner
to stdout on some platforms before `main` runs, so a redirected stdout is
best set at the top of `main`.

`print` writes through the stream this governs, so making stdout line- or
unbuffered is what gets output out in order when it is piped rather than on
a terminal. `stdout_write` flushes on every call and is unaffected.

**Parameters**

- `fd: integer` — Which stream to configure: 0=stdin, 1=stdout, 2=stderr.
- `mode: BufferMode` — Full (`iofbf`), line (`iolbf`), or no (`ionbf`) buffering.
- `size: integer` — Buffer size in bytes; 0 or less takes the default.

<a id="os.umask" />
```gust
def foreign umask(mask: integer) -> integer
```

<Note>
Not available on freestanding builds and Windows.
</Note>

Set the calling process's file-creation mask and return what it was.

Every bit set in `mask` is cleared from the permissions of a file or
directory the process goes on to create, whatever mode the creating call
asks for: with the common mask of 0o022, a file requested as 0o666 is
created 0o644. The mask constrains only permissions, never the rest of the
mode word, and it survives `fork` and an `exec` into another program —
which is why a process that launches others sets the mask it wants them to
inherit before it starts them.

This cannot fail, and the previous mask is only readable by replacing it.
Reading the current one without disturbing it means setting a mask and
putting the old one straight back.

**Parameters**

- `mask: integer` — Permission bits to withhold from newly created files.

<a id="os.fd_wait_readable" />
```gust
def foreign fd_wait_readable(fd: integer, timeout_ms: integer) -> bool
```

<Note>
Not available on freestanding builds.
</Note>

Wait until `fd` has data to read, for at most `timeout_ms` milliseconds.

A zero timeout tests readiness without waiting; a negative one waits with no
deadline. End of file counts as readable, since a read there returns at once
with zero bytes. Use this to keep a reader responsive to a deadline instead
of blocking in `read_fd` until bytes arrive.

**Parameters**

- `fd: integer` — Descriptor to wait on.
- `timeout_ms: integer` — Milliseconds to wait; 0 polls, negative waits indefinitely.

**Returns** `bool`

True when a read would not block, false when the wait elapsed first.
