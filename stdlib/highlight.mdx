---
title: highlight
description: "Syntax highlighting"
---

```gust
use highlight
```

Syntax highlighting. Turn a snippet of source code into colored output,
identifying each token (keyword, string, comment, and so on) and coloring it.

HTML scope class names are prefixed with `hljs-` and match the class names used
by common highlight themes, so an existing stylesheet renders the output.

**Examples**

For a terminal, get ANSI-colored text ready to print:
```gust
print(highlight.highlight_ansi("gust", source))
```

For the web, get HTML in which each token is wrapped in a `<span>` whose class
names a highlight theme's CSS can style:
```gust
result := highlight.highlight_code("python", source)
print(result.value)
```

To highlight many snippets in the same language, compile the grammar once and
reuse it:
```gust
prog := highlight.compile_named("python")
a := highlight.highlight_with(prog, source_a, "python")
prog.close()
```

## `HighlightResult`

<a id="HighlightResult" />
The outcome of highlighting a snippet.

```gust
def HighlightResult

    known: bool
    value: string
    relevance: integer
    illegal: bool
    language: string

end
```

**Fields**

- `known: bool` — Whether the requested language was recognized. When false, the value is the input escaped as plain text.
- `value: string` — The highlighted HTML.
- `relevance: integer` — A confidence score; higher means the source fits the language better.
- `illegal: bool` — Whether an illegal construct aborted highlighting.
- `language: string` — The language name that was applied.

## `MultiRegex`

<a id="MultiRegex" />
A single combined pattern that scans for many rules at once. Each rule
is one alternative wrapped in a capture group; the group that participates
in a match identifies which rule fired.

```gust
def MultiRegex

    combined: list[Regex]
    metas_by_group: dict[integer, MatchMeta]

end
```

**Fields**

- `combined: list[Regex]` — Zero or one compiled pattern (empty when the mode has no rules to scan for).
- `metas_by_group: dict[integer, MatchMeta]` — Map from a rule's wrapper group index to its meaning.

## `CompiledMode`

<a id="CompiledMode" />
A grammar rule prepared for scanning. Immutable once compiled; the
running highlighter keeps its own cursor state.

```gust
def CompiledMode

    id: integer
    scope: string
    begin_pat: string
    end_pat: string
    end_re: list[Regex]
    has_end_re: bool
    illegal_pat: string
    has_illegal: bool
    keywords: dict[string, KeywordHit]
    has_keywords: bool
    keyword_pattern: string
    keyword_re: list[Regex]
    relevance: integer
    contains_ids: list[integer]
    has_starts: bool
    starts_id: integer
    sub_language: string
    terminator_end: string
    exclude_begin: bool
    exclude_end: bool
    return_begin: bool
    return_end: bool
    ends_with_parent: bool
    ends_parent: bool
    skip: bool
    begin_callback: integer
    end_callback: integer
    matcher: MultiRegex

end
```

**Fields**

- `id: integer` — Index of this record in the program's mode table.
- `scope: string` — Scope span to wrap the region in, or "".
- `begin_pat: string` — Pattern that opens the region.
- `end_pat: string` — Pattern verified when the region's end fires.
- `end_re: list[Regex]` — Zero or one compiled `end_pat`.
- `has_end_re: bool` — Whether an end pattern exists.
- `illegal_pat: string` — Pattern that aborts on match.
- `has_illegal: bool` — Whether an illegal pattern exists.
- `keywords: dict[string, KeywordHit]` — Compiled keyword lookup.
- `has_keywords: bool` — Whether keyword processing applies.
- `keyword_pattern: string` — Pattern that carves keyword candidates from text.
- `keyword_re: list[Regex]` — Compiled `keyword_pattern`.
- `relevance: integer` — Confidence weight contributed when the region closes.
- `contains_ids: list[integer]` — Compiled ids of nested modes.
- `has_starts: bool` — Whether a follow-on mode begins when this region ends.
- `starts_id: integer` — Compiled id of the follow-on mode, or -1.
- `sub_language: string` — Embedded language name, or "".
- `terminator_end: string` — End pattern used while scanning inside this region.
- `exclude_begin: bool` — Keep the begin match out of the scope.
- `exclude_end: bool` — Keep the end match out of the scope.
- `return_begin: bool` — Rewind to re-scan the begin match inside the region.
- `return_end: bool` — Rewind to let the parent re-scan the end match.
- `ends_with_parent: bool` — End when the parent's end fires.
- `ends_parent: bool` — Ending this region ends the parent too.
- `skip: bool` — Buffer content into the parent rather than emitting it here.
- `begin_callback: integer` — `CB_*` tag run on begin.
- `end_callback: integer` — `CB_*` tag run on end.
- `matcher: MultiRegex` — Combined scanner for the rules active inside this region.

## `Emitter`

emitter behaves as a shared sink even when passed by value.


- `class_prefix: string` — Prefix applied to top-level scope class names (HTML).

- `last_index: integer` — Index of the previous firing.
- `format: integer` — Output format passed to the emitter (`FORMAT_HTML`/`FORMAT_ANSI`).

## `Mode`

<a id="Mode" />
One grammar rule.

A rule matches with `begin` (or the shorthand `match_`, which is copied
into `begin`) and, for a spanning region, closes with `end_`. Nested rules
listed in `contains` apply between the begin and end. Most fields are
optional; a leaf rule often sets only `scope` and `begin`.

```gust
def Mode

    scope: string
    begin: string
    end_: string
    match_: string
    illegal: string
    contains: list[Mode]
    keywords: dict[string, string]
    keyword_pattern: string
    begin_keywords: string
    relevance: integer
    variants: list[Mode]
    starts: list[Mode]
    sub_language: string
    exclude_begin: bool
    exclude_end: bool
    return_begin: bool
    return_end: bool
    ends_with_parent: bool
    ends_parent: bool
    skip: bool
    is_self: bool
    begin_callback: integer
    end_callback: integer

end
```

**Fields**

- `scope: string` — CSS scope name for the matched region (e.g. "string", "comment.line"). Empty means the region emits no wrapping span.
- `begin: string` — Pattern that opens the region.
- `end_: string` — Pattern that closes a spanning region. Empty for a leaf rule.
- `match_: string` — Shorthand for a single-shot `begin` with no `end_`.
- `illegal: string` — Pattern whose match aborts highlighting as invalid.
- `contains: list[Mode]` — Nested rules that apply inside this region.
- `keywords: dict[string, string]` — Map of scope name to a space-separated keyword list; a bare keyword list uses the scope "keyword".
- `keyword_pattern: string` — Pattern that carves `keywords` candidates out of text; defaults to a word run.
- `begin_keywords: string` — Space-separated words that open the region on a word boundary; sets up keyword scoring and dot-skipping automatically.
- `relevance: integer` — Confidence weight; -1 leaves it at the default of 1.
- `variants: list[Mode]` — Alternate versions of this rule; each expands into its own rule at compile time.
- `starts: list[Mode]` — The rule to switch into after this region ends (0 or 1 entry).
- `sub_language: string` — Name of another language to highlight the region's contents with.
- `exclude_begin: bool` — Keep the begin match out of the region's scope.
- `exclude_end: bool` — Keep the end match out of the region's scope.
- `return_begin: bool` — Rewind so the begin match is re-scanned inside the region.
- `return_end: bool` — Rewind so the end match is re-scanned by the parent.
- `ends_with_parent: bool` — End this region when the parent's end matches.
- `ends_parent: bool` — Ending this region also ends the parent.
- `skip: bool` — Match and advance but emit the content into the parent buffer.
- `is_self: bool` — Sentinel entry meaning "this mode itself" inside `contains`.
- `begin_callback: integer` — One of the `CB_*` tags run when the begin matches.
- `end_callback: integer` — One of the `CB_*` tags run when the end matches.
