The classic Bluetooth radio: BR/EDR, which is the radio a serial port, a
printer, a headset or a keyboard speaks, and what a phone means when it offers
to pair with something.

This is a different radio from the low-energy one the `bluetooth` package
serves, not a different protocol over the same one, and above the antenna the
two have almost nothing in common. A low-energy peripheral publishes attributes
another device reads, writes and subscribes to. A classic device opens a
*channel*: a stream of bytes running in both directions, whose contents are the
profile's business rather than this package's. They are separate packages for
that reason, and because a program that wants one should not pay for the other
— on a board the classic stack is tens of kilobytes of code a low-energy program
has no use for.

RFCOMM is the protocol that carries those byte streams. A channel is a number
from 1 to 30 that the *serving* device assigns, so it cannot be predicted from
the profile: ask the device with `rfcomm_channel`, which reads it out of the
device's own service record, and hand the answer to `rfcomm_connect`.
`rfcomm_listen` serves one.

Linux and the Raspberry Pi Pico 2 W both carry the whole surface, and a program
written against either builds for the other. What differs is what each has to do
for itself: a Linux host has a system Bluetooth daemon that owns discovery, the
service record and the device name, and a board has none — so `discover`, and
the `name` argument to `rfcomm_listen`, exist on the board and not on the host.
Every other target has no classic backend, so importing this package there is a
compile error rather than a misleading no-op.

UUIDs come from the `bluetooth` package, since a UUID means the same thing on
both radios, and the service classes worth naming are in `ServiceClass`.

Example — connect to a device's serial port profile and exchange a line:
```gust
use bluetooth

use bluetooth.classic

use ServiceClass from bluetooth.enums.uuids

def main() -> none
    address := "AA:BB:CC:DD:EE:FF"
    channel := classic.rfcomm_channel(
        address,
        bluetooth.UUID(value: ServiceClass.SerialPort),
    )
    with classic.rfcomm_connect(address, channel) as port
        port.send(b"AT\r")
        print(port.receive() as string)
    end
end
```

**Methods**

<a id="A2dpSink.accept" />
```gust
def A2dpSink.accept(timeout_ms: integer) -> A2dpStream
```

Wait for a device to connect and start sending audio, and return the
stream it is sending.

A device that is not yet paired pairs as it connects. Agreeing the coding
takes several exchanges after that, and this returns only once audio is
actually flowing, so the stream handed back is ready to be read.

## `A2dpStream`

<a id="A2dpStream" />
Audio a device is sending. `A2dpSink.accept` returns one; `close`, or
leaving the `with` block holding it, ends the stream.

The shape of the audio is fixed for the stream's life: it is what the two
devices agreed before the first sample arrived, and a device that wants to
change it starts a new stream.

```gust
def A2dpStream

    address: string
    sample_rate: integer
    channels: integer
    timeout_ms: integer
    _handle: integer
    _decoder: SbcDecoder
    _open: ref[bool]

end
```

**Fields**

- `address: string` — The sending device's address, as "AA:BB:CC:DD:EE:FF".
- `sample_rate: integer` — Samples per second, one of 16000, 32000, 44100 or 48000.
- `channels: integer` — 1 for mono audio, 2 for stereo.
- `timeout_ms: integer` — How long one read may wait before it raises. 0 waits indefinitely.
- `_handle: integer` — What the backend identifies the stream by.
- `_decoder: SbcDecoder` — Holds what the coding needs remembered between packets.
- `_open: ref[bool]` — False once the stream has been closed locally.

**Methods**

<a id="A2dpStream.receive" />
```gust
def A2dpStream.receive() -> bytes
```

The next packet of audio, as 16-bit signed samples, least-significant
byte first, with the channels interleaved.

Waits for a packet and returns as soon as one has arrived. How much audio
one packet carries is the sending device's choice and varies, so a program
playing this should hand whatever it gets to the sound device rather than
expect a fixed amount.

Empty `bytes` means the device stopped sending.

**Raises**

- `IOError` — If the stream is closed, the link fails, or nothing arrives within the stream's timeout.

---

<a id="A2dpStream.is_open" />
```gust
def A2dpStream.is_open() -> bool
```

True until the stream is closed locally. A device that stops sending is
noticed at the next `receive`, which returns empty `bytes`.

---

<a id="A2dpStream.close" />
```gust
def A2dpStream.close() -> none
```

End the stream. Idempotent, so closing twice is harmless and a `with`
block may be left early.

## `AvrcpRemote`

<a id="AvrcpRemote" />
An open control connection, from either end. `avrcp_connect` returns one
for a device this program took the controls of; `AvrcpListener.accept`
returns one for a device that took this program's.

Which end opened it makes no difference to what can be done over it: the
protocol runs both ways at once, so a connection a phone opened is still one
this program can send a key press down.

```gust
def AvrcpRemote

    address: string
    timeout_ms: integer
    _handle: AvrcpLink
    _open: ref[bool]

end
```

**Fields**

- `address: string` — The other end's address, as "AA:BB:CC:DD:EE:FF".
- `timeout_ms: integer` — How long one exchange may wait before it raises. 0 waits indefinitely.
- `_handle: AvrcpLink` — The backend's own record of the connection.
- `_open: ref[bool]` — False once the connection has been closed locally.

**Methods**

<a id="AvrcpRemote.press" />
```gust
def AvrcpRemote.press(key: AvrcpKey) -> none
```

Press and release one key of the other device's transport controls.

The key is released as well as pressed, so a device is never left holding
one down. `fast_forward` and `rewind` therefore move by one step per call
rather than winding while something is held.

**Parameters**

- `key` — Which key to press.

**Raises**

- `IOError` — If the connection is closed, the device refuses the key, or it does not answer within the connection's timeout.

## `RfcommConnection`

<a id="RfcommConnection" />
An open serial connection over the classic radio, from either end.
`rfcomm_connect` returns one for a device this program reached;
`RfcommListener.accept` returns one for a device that reached this program.

The connection carries bytes, not messages: what one `send` writes may
arrive across several `receive` calls, and several sends may arrive
together. A protocol spoken over it has to say where its own messages end.

```gust
def RfcommConnection

    address: string
    channel: integer
    timeout_ms: integer
    _handle: integer
    _open: ref[bool]

end
```

**Fields**

- `address: string` — The other end's address, as "AA:BB:CC:DD:EE:FF".
- `channel: integer` — The RFCOMM channel the connection runs on.
- `timeout_ms: integer` — How long one send or receive may wait before it raises. 0 waits indefinitely.
- `_handle: integer` — What the backend identifies the open channel by.
- `_open: ref[bool]` — False once the connection has been closed locally.

**Methods**

<a id="RfcommConnection.send" />
```gust
def RfcommConnection.send(data: bytes) -> none
```

Send every byte of `data` to the other end.

A payload larger than one packet blocks until all of it has left.

**Parameters**

- `data` — The payload to send.

**Raises**

- `IOError` — If the connection is closed or the link fails mid-send.

---

<a id="RfcommConnection.receive" />
```gust
def RfcommConnection.receive(max: integer) -> bytes
```

Whatever the other end has sent that this end has not read yet, up to
`max` bytes.

Waits for the first byte and returns as soon as anything has arrived, so a
reply longer than one packet takes more than one call to read. Empty `bytes`
means the other end closed the connection.

**Parameters**

- `max` — Most bytes to return from this call.

**Raises**

- `IOError` — If the connection is closed, the link fails, or nothing arrives within the connection's timeout.

---

<a id="RfcommConnection.is_open" />
```gust
def RfcommConnection.is_open() -> bool
```

True until the connection is closed locally. An other end that drops the
link is noticed at the next `receive`, which returns empty `bytes`.

---

<a id="RfcommConnection.close" />
```gust
def RfcommConnection.close() -> none
```

End the connection. Idempotent, so closing twice is harmless and a `with`
block may be left early.

## `ClassicDevice`

<a id="ClassicDevice" />
<Note>
Only available where `has("bt-classic")`.
</Note>

One classic device an inquiry found. Its `address` is what
`rfcomm_channel` and `rfcomm_connect` take.

A classic address is burned into the device and does not rotate, so it is a
durable identity — unlike the address a low-energy device advertises.

```gust
def ClassicDevice

    address: string
    name: string
    device_class: integer
    rssi: integer | none

end
```

**Fields**

- `address: string` — The device's address, as "AA:BB:CC:DD:EE:FF".
- `name: string` — The name the device gave, or "" if it would not give one.
- `device_class: integer` — The assigned class-of-device code, which says what kind of thing the device is — a phone, a headset, a computer.
- `rssi: integer | none` — Signal strength in dBm of the device's answer, negative and closer to zero when nearer, or `none` when the controller did not measure one.

<a id="bluetooth.classic.sink_class_of_device" />
```gust
def sink_class_of_device(device: bluetooth.enums.core.CodDeviceClassAudioVideoMinor) -> integer
```

The assigned class-of-device code for an audio sink of kind `device`.

A class of device is what a device publishes to say what it is, and what
`ClassicDevice.device_class` reports for a device that was found. `a2dp_sink`
composes this for the board it serves, so a program that only wants a speaker
on the air has no need to call it; it is here for a program that reads a code
off one device and wants to say how another compares.

The code is three fields in one number: the services the device offers, a
bit each; the major class, five bits from bit 8; and the minor class, six
bits from bit 2, which the major class gives the meaning of.

Every sink offers the same two services, and the pair is what says which end
of the audio the device is — audio alone says it deals in sound, and
rendering alongside it says sound ends here rather than starts here.

**Parameters**

- `device: bluetooth.enums.core.CodDeviceClassAudioVideoMinor` — What kind of audio device is being published.

<a id="bluetooth.classic.discover" />
```gust
def discover(timeout_ms: integer) -> list[ClassicDevice]
```

<Note>
Only available where `has("bt-classic")`.
</Note>

Ask every classic device in range to answer, for `timeout_ms`, and return
each one that did.

Only devices currently willing to be found answer: a phone answers while its
Bluetooth settings screen is open and often not otherwise.

An inquiry runs in steps of 1.28 seconds and always finishes the step it is
in, so it takes a little longer than asked, and anything under one step is
rounded up to one. A device that answers without giving a name is then asked
for one directly, which takes a moment more; one that does not answer that
promptly is left unnamed rather than holding up the rest.

**Parameters**

- `timeout_ms: integer` — Milliseconds to keep asking for.

**Raises**

- `IOError` — If the radio cannot be brought up.
