title: ioctl
description: "Device control through the POSIX `ioctl` call"
---

```gust
use ioctl
```

Device control through the POSIX `ioctl` call. A request is identified by its
numeric code (device-specific, defined by the kernel headers for the device in
question). The third argument is passed straight through as an `integer`: for
requests that read or write a struct, allocate a buffer with `unsafe.alloc`
and pass its address; for requests that take a scalar by value, pass the value
directly; for requests that take nothing, pass 0.

Available on native builds for Linux, macOS and the BSDs. Windows, the
microcontroller targets and the browser have no `ioctl` package: an import there
resolves to nothing and every reference is a compile error.

**Examples**

```gust
use ioctl
use unsafe

def main() -> none
    fd := ...                       # an open device fd
    buf := unsafe.alloc(256)        # room for the request's struct
    rc := ioctl.call(fd, 0x4600, buf)   # e.g. FBIOGET_VSCREENINFO
    if rc == 0
        width := unsafe.load32(buf, 0)  # first field of the struct
    end
    unsafe.free(buf)
end
```

<Note>
Only available on native builds, and not on Windows.
</Note>

## Functions

<a id="ioctl.call" />
```gust
def foreign call(fd: integer, request: integer, arg: integer) -> integer
```

Issue `request` on `fd`, passing `arg` as the request's third argument.
Returns the call's result (0 on success for most requests), or -1 on error.

**Parameters**

- `fd: integer` — An open file descriptor for the device.
- `request: integer` — The device-specific request code from the kernel headers, or one assembled by the builders below.
- `arg: integer` — The request's third argument — an address of a struct buffer, a scalar value, or 0 when the request takes none.

---

<a id="ioctl.request" />
```gust
def foreign request(kind: integer, number: integer) -> integer
```

The code for a request that carries no data, from the driver's `_IO`
spelling.

**Parameters**

- `kind: integer` — The driver's identifying character, e.g. `"H"` as an integer for the Bluetooth requests.
- `number: integer` — The request's number within that driver.

---

<a id="ioctl.read_request" />
```gust
def foreign read_request(
    kind: integer,
    number: integer,
    size: integer,
) -> integer
```

The code for a request the driver fills in, from its `_IOR` spelling.

**Parameters**

- `kind: integer` — The driver's identifying character as an integer.
- `number: integer` — The request's number within that driver.
- `size: integer` — Size in bytes of the struct the driver writes.

<a id="ioctl.write_request" />
```gust
def foreign write_request(

    size: integer,
) -> integer
```

The code for a request the caller fills in, from its `_IOW` spelling.

**Parameters**

- `kind: integer` — The driver's identifying character as an integer.
- `number: integer` — The request's number within that driver.
- `size: integer` — Size in bytes of the struct the caller supplies.

def foreign read_write_request(

The code for a request both sides fill in, from its `_IOWR` spelling.

**Parameters**

- `kind: integer` — The driver's identifying character as an integer.
- `number: integer` — The request's number within that driver.
- `size: integer` — Size in bytes of the struct passed both ways.
